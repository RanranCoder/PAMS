# 签到应签名单与核验字段方案（PAMS 三期）

## 一、需求概述

在现有签到功能（手动签到 + 扫码签到）基础上新增：

1. **应签名单设置**：允许上传 Excel 名单作为签到核验来源（判定"应到"名单）
2. **自定义核验字段**：允许用户配置签到人需要输入的信息（如姓名/学号/手机号/班级，字段可增删、设必填）
3. **已签/未签显示与筛选**：设置应签名单后，展示已签/未签列表（带筛选）
4. **手动补签**：未签名单可勾选补签（写入签到记录，标记手动）

## 二、核心设计决策（已确认）

| 决策点 | 选择 | 说明 |
|---|---|---|
| 已签/未签判定 | **自定义字段匹配** | 按用户配置的核验字段（如姓名+学号）匹配应签名单行 |
| 核验字段配置 | **设置页配置** | 签到 Tab 提供字段配置面板，扫码落地页动态生成表单 |
| 未签处理 | **可手动补签** | 未签名单勾选补签，写入签到记录（signType=MANUAL） |

## 三、数据模型（后端新增）

### 3.1 表：`signin_roster`（应签名单行）
每行 = 一个应签人。列：核验字段值以 JSON 存，或固定列 + 扩展 JSON。

```
signin_roster
├── id BIGINT PK
├── activity_id BIGINT NOT NULL FK→activity
├── fields_json TEXT      -- {"姓名":"张三","学号":"2025001","手机号":"138..."} 核验字段值
├── created_at DATETIME
```

> 用 `fields_json` 存核验字段值（键=字段名，值=该人对应值），字段名由配置表决定。灵活适配"自定义字段"。

### 3.2 表：`signin_field_config`（核验字段配置）
每活动一行记录一个字段。

```
signin_field_config
├── id BIGINT PK
├── activity_id BIGINT NOT NULL FK→activity
├── field_name VARCHAR(50)   -- 字段显示名（如"姓名"/"学号"/"手机号"）
├── field_key VARCHAR(50)    -- 字段键（如 name/studentNo/phone/className）
├── required TINYINT         -- 是否必填
├── field_type VARCHAR(20)   -- 字段类型（TEXT/NUMBER/PHONE 等）
├── sort_order INT
├── created_at DATETIME
```

### 3.3 后端接口
| 接口 | 说明 |
|---|---|
| `POST /api/signins/roster/upload` | 上传 Excel 名单（multipart），按字段配置解析导入 signin_roster（复用 RosterImportService 的 xlsx 解析思路） |
| `GET /api/signins/roster?activityId=` | 应签名单列表（含每行已签/未签状态） |
| `DELETE /api/signins/roster/{id}` | 删除名单行 |
| `GET /api/signins/fields?activityId=` | 核验字段配置 |
| `PUT /api/signins/fields` | 保存核验字段配置（活动级） |
| `GET /api/signins/summary?activityId=` | 已签/未签/应签汇总（供 Tab 顶部统计 + 筛选） |
| `POST /api/signins/backfill` | 手动补签（从应签名单写入签到记录） |
| 修改 `POST /api/signins/scan` | 扫码时若活动配置了核验字段，按字段匹配应签名单（匹配到则标记该名单行已签） |

### 3.4 已签/未签判定逻辑
- **已签**：应签名单行被某条签到记录匹配（按核验字段值匹配：所有 required 字段值相等即算匹配到）
- **未签**：应签名单行未被任何签到记录匹配
- 无应签名单时：签到列表照旧，不显示已签/未签统计

## 四、前端界面

### 4.1 签到 Tab（SigninPanel）增强
- **顶部**：加"应签名单"配置区——上传 Excel 按钮 + 核验字段配置入口 + 汇总统计（应签 X / 已签 Y / 未签 Z）
- **名单列表**：应签名单表格（列 = 核验字段 + 状态[已签/未签]），带筛选（全部/已签/未签）
- **未签补签**：未签行勾选 → 补签按钮 → 写入签到记录
- **已有签到列表**：保留原签到记录列表（含扫码/手动记录）

### 4.2 核验字段配置面板
- 字段列表（字段名/是否必填/类型），可增删改
- 保存后扫码落地页动态生成表单

### 4.3 扫码落地页（SigninScan）动态化
- 加载活动核验字段配置 → 动态生成表单（按 required 标记必填）
- 提交时把各字段值随 token 一起 POST /api/signins/scan
- 若匹配应签名单 → 签到成功标记该行已签；不匹配 → 提示"未在应签名单中"（可选：仍允许签到或拒绝）

### 4.4 Excel 上传格式
- 表头 = 核验字段名（姓名/学号/手机号/班级…），每行 = 一个应签人
- 解析时按字段配置的 field_key 映射到 fields_json
- 过滤空行、~$ 临时文件（复用一期迁移脚本思路）

## 七、风险与说明

- **自定义字段匹配的歧义**：若只配"姓名"一个必填字段，重名会误判已签/未签。建议字段配置默认含姓名+学号，或提示"姓名可能重名，建议加学号"。核验字段匹配时：**所有必填字段值都相等才算匹配**。
- **Excel 解析**：复用一期 `RosterImportService` 的 xlsx 解析能力（POI），按字段配置映射列。表头不匹配时给出清晰错误。
- **scan 接口改造兼容性**：不设名单/字段配置时行为不变（仍姓名+学号），已设名单但签到人不匹配——**可选策略**：a) 拒绝签到（严格）；b) 允许签到但不计入应签（宽松）。默认宽松（避免现场进不去），报告说明。
- **补签**：补签记录 signType=MANUAL + 备注"应签名单补签"，计入已签。
- **筛选**：全部/已签/未签三个 Tab 或 Select 筛选。
