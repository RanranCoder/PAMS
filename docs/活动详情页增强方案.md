# 活动详情页增强方案（PAMS 二期）

## 一、需求概述

对活动详情页的 5 个 Tab 进行业务加工，全部基于现有前后端，不新增后端业务模块（扫码签到例外，需新增一个后端接口）：

| Tab | 现状 | 增强目标 |
|---|---|---|
| 基本信息 | Descriptions 展示 + 状态操作 | **直接预览甘特图和关联文件**；点"编辑"进入独立详情编辑页 |
| 策划书 | 7 个 TextArea 表单 | **Word 文档形式预览/编辑切换**，内嵌简易 Word 编辑器，支持导入导出，以参考策划书为模板 |
| 议程表 | 增删改表格 | **允许导出议程表**（Word/Excel） |
| 座位表 | 标签流展示 + 表单管理 | **图表形式展示（电影选座风格）** + Excel 风格 + 内嵌简易 Excel 编辑器，能设置图例、图例区域显示标签 |
| 签到 | 手动签到 + CSV 导出 | **新增扫码签到**（二维码手动刷新，未刷新长期有效） |

## 二、技术选型（已确认）

| 组件 | 选型 | 体积(gzip) | 说明 |
|---|---|---|---|
| Word 编辑器 | **自绘 contenteditable** + 结构化模板 | ~0 | A4 白纸样式，预置策划书 12 章结构模板，三档字号（宋体 22/14/12pt）+ 4 列预算表 |
| Word 导入 | **mammoth**（按需懒加载） | 121KB | docx → HTML 填充编辑器 |
| Word 导出 | **docx**（@nativedocuments） | 113KB | 前端从结构化数据生成 .docx 下载 |
| Word 预览 | **docx-preview**（按需懒加载） | 48KB | 既有 docx 文件 Word 纸张式预览 |
| Excel 编辑器 | **Handsontable**（MIT 版） | ~100KB | 类 Excel 网格编辑；若 MIT 版不可用则降级自绘 antd 表格编辑 |
| 二维码 | **qrcode.react** | ~10KB | 渲染签到二维码 |
| 选座 UI | **自绘 CSS Grid** | 0 | 电影选座风格，与 liquid-glass 设计系统一致 |

> 注意：Handsontable 自 8.x 起分商业版（付费）与 MIT 版（7.x 及之前 / @handsontable 7.x）。需在安装时确认选择 MIT 许可版本。若无法获得 MIT 版，降级方案为自绘 Excel 风格表格编辑器。

## 三、功能设计

### 3.1 基本信息 Tab（甘特图 + 关联文件 + 编辑入口）

- **甘特图预览**：在基本信息 Tab 内嵌只读甘特图（复用 `GanttChart` 组件，`onEdit` 不传 → 只读/精简编辑），数据来自 `GET /api/tasks?activityId=`。提供"查看完整甘特图"跳转 `/activities/:id/gantt`。
- **关联文件**：在基本信息 Tab 内嵌"关联文件"列表——按活动查 `GET /api/materials?activityId=`（bizType 分类展示），点击下载（复用 `downloadFile`）。文件上传入口跳转材料库或内嵌 UploadFile。
- **编辑入口**：页面头部加"编辑"按钮 → 跳转独立路由 `/activities/:id/edit`。

### 3.2 独立编辑页（/activities/:id/edit）

- 复用现有 `ActivitySave` 接口（`updateActivity`），表单含：名称/主题/类型 Select/起止 DatePicker/地点/组织单位/面向对象/主持人/负责人/描述。
- 保存后 `navigate('/activities/:id')` 返回详情并刷新。
- 权限：所有登录用户可编辑（现有后端无 @PreAuthorize 限制）。

### 3.3 策划书 Tab（Word 预览/编辑 + 导入导出）

**数据模型**：沿用现有 `activity_plan` 7 字段（background/purpose/content/flow/notice/emergency/budget）。增加一个**可选**字段 `docxVersion`？——不，保持现有模型，Word 编辑器只是这 7 个字段的"Word 纸张化编辑/渲染视图"，数据仍存 7 字段，不做整篇文档存储。

**两种模式**：
1. **预览模式**：A4 白纸样式渲染 7 字段为策划书文档（12 章结构 + 预算表），只读。若该活动有已上传的 .docx 策划书文件（材料库 bizType=PLAN），提供 docx-preview 渲染。
2. **编辑模式**：contenteditable 编辑器，预置 12 章模板骨架，可编辑章节内容 + 预算表（加行/删行/填值）。工具条：字号（22/14/12pt 三档）、加粗、对齐、列表、插入表格。
   - **导入**：上传 .docx → mammoth 转 HTML → 填入编辑器（可继续编辑）。
   - **导出**：编辑器内容 → docx 库生成 .docx 下载（宋体、标题层级、表格）。

**模板**：以参考策划书"策划书新模板(终)1.docx"的 12 章结构为骨架：
一、活动名称 / 二、活动主题 / 三、活动背景 / 四、活动目的 / 五、活动时间 / 六、活动地点 / 七、活动组织单位 / 八、活动对象 / 九、活动内容（前期/中期/流程/后期）/ 十、活动注意事项 / 十一、应急预案 / 十二、经费预算（4 列表格）+ 落款。

### 3.4 议程表 Tab（导出）

- 保留现有增删改。
- 新增**导出**按钮：把议程列表导出为 Word（docx，编号列表）或 Excel（xlsx）。默认 Word（符合党务文档习惯），提供格式选择。

### 3.5 座位表 Tab（图表化 + Excel 编辑 + 图例）

**数据模型**：沿用现有 `seat_map`（zone/rowNo/colNo/personName/seatType）。

**展示模式（选座风格）**：
- CSS Grid 绘制座位矩阵：按 `rowNo × colNo` 排布，每个座位一个圆角格子。
- **图例**：按 `seatType`（领导席/观众席/礼仪/工作人员等）区分颜色，底部/侧边图例条（色块 + 标签）。也支持按 `zone`（区域）区分。
- **区域标签**：每个 zone 区域顶部显示区域名标签（如"第一党支部"），图例对应的区域在矩阵中显示其标签。
- 座位状态：可选/已占（有 personName）/禁选。点击已占座位显示就座人信息。

**编辑模式（Excel 风格）**：
- Handsontable 网格：列 = 区域/排/列/座位类型/就座人，行 = 每个座位。类 Excel 增删行/编辑单元格。
- **图例设置**：一个配置面板，定义 seatType → 颜色映射，可增删改；配置保存后矩阵视图按图例着色。
- 数据同步：编辑后批量保存到后端（复用 createSeat/updateSeat/deleteSeat，或新增批量接口）。

**图例设置的持久化**：图例（seatType → 颜色）本身存哪？两个选项：
- a) 存后端（新增表或复用 seat_map 的 seatType 枚举）——需后端改动
- b) 前端 localStorage 按活动缓存——零后端改动，但换设备丢失

**倾向 a 的轻量版**：图例定义存前端，但随座位数据隐含（seatType 从现有数据聚合）。即：图例颜色映射由前端按 seatType 自动分配（散列到设计系统色板），用户可在编辑面板自定义覆盖（localStorage 持久化）。这样零后端改动，且图例标签 = seatType 本身。

### 3.6 签到 Tab（扫码签到）

**后端新增**（唯一需后端改动处）：
- `POST /api/signins/token`：生成一次性签到令牌（activityId + 随机 token + 过期时间），返回 `{token, qrContent, expiresAt}`。令牌可长期有效（如 24h）直到手动刷新。
- `POST /api/signins/scan`：公开接口（免登录）——扫码后浏览器 POST `{token, name, studentNo}` 写入签到记录（signType=SCAN）。校验令牌有效 + 活动存在 + 未过期。
- 令牌存储：内存 Map 或数据库表。简单起见用**内存 Map**（`ConcurrentHashMap<token, {activityId, expiresAt}>`），重启失效（可接受，校园内部场景）。或复用现有 signin 表 + 一个 signin_token 字段——不，保持内存实现最简单。

**前端**：
- 签到 Tab 顶部加"扫码签到"卡片：显示二维码（`qrcode.react` 渲染 `qrContent`，内容为一个短链接 `{origin}/signin/{token}` 或直接编码 token）。
- **手动刷新**按钮：点击生成新令牌（旧令牌作废），二维码更新。未刷新时长期有效（令牌不过期或长过期）。
- 扫码后手机打开链接 → 一个轻量签到页（免登录，填姓名/学号 → POST scan → 成功提示）。这个签到页要新增路由 `/signin/:token`（在 MainLayout 之外，独立页面）。
- 签到记录刷新：扫码成功后，签到 Tab 列表自动刷新（轮询或手动）。

## 五、实施顺序（里程碑）

1. **M1 依赖与基础设施**：安装前端新依赖；后端 SigninService token/scan + 控制器 + Security 放行 + 测试
2. **M2 基本信息 Tab 增强**：甘特图预览嵌入 + 关联文件列表 + 编辑入口 + 独立编辑页（/activities/:id/edit）
3. **M3 策划书 Word 编辑器**：planTemplate（12 章模板）+ WordEditor（contenteditable）+ WordPreview（A4 渲染）+ 导入（mammoth）+ 导出（docx）
4. **M4 议程导出 + 座位表图表化**：议程导出 Word/Excel；SeatMapView（选座矩阵 + 图例 + 区域标签）；SeatExcelEditor（Excel 编辑 + 图例设置）
5. **M5 扫码签到**：SigninQR（二维码 + 手动刷新）+ SigninScan 落地页 + 后端 token/scan 联调
6. **M6 联调打磨**：全流程验证、边界处理、明暗主题适配、提交

## 六、风险与说明

- **Handsontable MIT 版**：需确认 `@handsontable/react` 的 MIT 版本可用；若不可用，降级为自绘 Excel 风格表格（antd Table + Input 单元格），功能降级但图例/矩阵不受影响。
- **docx-preview / mammoth 体积**：按需懒加载（React.lazy / 动态 import），避免进主包。
- **扫码签到免登录接口**：`/api/signins/scan` 是公开 POST，需防滥用——令牌机制本身就是门禁（不知道有效 token 无法签到），且令牌 24h 过期 + 手动刷新作废。令牌随机强度足够。
- **图例持久化**：前端 localStorage 按活动缓存（零后端改动）；图例标签即 seatType。
- **策划书数据兼容**：现有 7 字段可能存的是纯文本或 JSON，Word 渲染需兼容两种（复用现有 parseJsonField 思路）。
