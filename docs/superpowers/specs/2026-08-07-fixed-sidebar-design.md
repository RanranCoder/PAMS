# 桌面端固定侧边栏设计

## 目标

桌面端页面滚动时，左侧导航栏保持固定；右侧仅内容区域纵向滚动。暂不处理移动端适配。

## 现状

`pams-web/src/layouts/MainLayout.tsx` 使用 Ant Design 的 `Layout`、`Sider`、`Header` 和 `Content`。当前外层布局只有 `minHeight: 100vh`，右侧布局和内容没有独立高度及滚动边界，因此浏览器页面整体滚动时侧边栏会随页面移动。

## 方案

采用布局级独立滚动，不使用全局 `position: fixed`：

- 外层 `Layout` 设置 `height: 100vh` 和 `overflow: hidden`，限制页面滚动范围。
- `Sider` 保持现有桌面端宽度、边距、圆角和菜单行为，设置 `height: 100vh`；菜单内容超出时允许侧边栏内部滚动。
- 右侧 `Layout` 设置 `height: 100vh`、`minWidth: 0`，避免内容宽度溢出影响布局。
- `Content` 设置 `overflow-y: auto`，并保留现有内边距；右侧页面内容由此独立滚动。
- 不改变路由、菜单选中逻辑、Header 行为、弹窗及移动端专属适配。

布局关系：

```text
视口 100vh
├── Sider：固定，占满视口，内部必要时滚动
└── 右侧 Layout：占满视口
    ├── Header：固定在右侧顶部
    └── Content：独立纵向滚动
```

## 交互与边界

- 鼠标滚轮在右侧内容区滚动时，侧边栏位置不变。
- 菜单过长时，侧边栏自身可以滚动，不推动右侧内容。
- Header 不随 Content 内容滚动。
- 不引入新的依赖，不修改全局样式。

## 验证

- 运行前端开发服务器，确认页面正常渲染且无控制台错误。
- 桌面视口下检查长内容滚动：Sider 位置保持不变，Content 发生纵向滚动。
- 检查菜单点击、路由切换和现有 Header 操作未受影响。
- 检查桌面端布局无横向滚动条。
